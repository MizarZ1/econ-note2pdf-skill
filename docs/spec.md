# v0.1 产品与实现规格

状态：实施规格。运行时字段的唯一详细定义见 [内容契约](../advanced-econ-note2pdf/references/content-model.md)；变更字段必须同步实现和调用示例。

## 产品与模式

输入为有序的板书照片或手写 PDF。首版支持 JPEG、PNG、WebP、BMP、TIFF 和 PDF；HEIC/HEIF 依赖本机解码器。多页 PDF/TIFF 按页展开，显式文件列表保留输入顺序；目录采用自然排序并标为建议顺序，宿主核对。相同材料不自动删除。

模型识别由宿主完成，脚本不发送材料到任何模型 API。宿主需要视觉、读写本地文件、执行 Python/LaTeX 和向用户提问的能力；无视觉能力不能声称完成转录。

三种模式：`faithful` 忠实保留原文与步骤；`study` 按学习逻辑整理并补充必要解释；`both` 从同一来源生成两套工程与 PDF。未指定时问一次，之后沿用选择。界面向用户使用中文模式名。

原文错误在忠实版保留并记录；复习版可更正，但须在来源记录/附录中保留修正依据。新增假设必须出现在使用位置；不能用默认模型、函数或数据填补无法辨认的材料。

正文围绕问题、假设与记号、推导、结论与经济含义组织，避免工具状态和反复免责。一般待确认事项及必要的更正说明置于附录；关键符号/条件/内容不明并影响结论时，在对应内容块加入简短提示。技术日志不进入学术附录。没有需要说明的事项时不生成复核附录。

## 边界

不提供独立 OCR、联网模型接口、网页服务、模型训练或自动数学正确性证明。图像增强和结构校验不代表识别完成。经济学图表由宿主理解后编写 TikZ/PGFPlots，确实无法还原时将局部截图和原因放入附录；不承诺自动从曲线恢复数值。DSH 专用接口尚待核实，通用工作流不依赖它。

## 工作目录

```text
project.json              # 项目元数据、来源列表、单元顺序、素材、符号表
originals/                # 按编号复制的原始输入；不覆盖
prepared/<source>/<rev>/  # EXIF 校正后的全图、变换后图像、预览和高清分块
assets/                   # 原图区域等可交付素材
units/<unit>.json         # 宿主编写的逻辑单元、覆盖清单、内容块和学术事项
content/                  # 宿主编写的独立 LaTeX 正文片段
state.json                # 带内容指纹的复核与构建状态
history/                  # 工具替换文件或重新组装前的版本
build/<mode>/             # 可独立编译的 LaTeX 工程，成功时包含 main.pdf
previews/<mode>/          # 对本次成功 PDF 渲染的页面图像
logs/                     # 每次命令/编译诊断，失败也保留
output/                   # 打包的交付文件
```

所有相对文件路径限定在项目内。初始化只接受不存在或空的目标目录，不能覆盖已有项目。写 JSON 使用临时文件和原子替换；再次运行处理命令可复用相同参数的产物。用户修改内容文件后，下次状态查询自动判断旧复核/构建是否过期。

## 处理与来源

原始文件以 SHA-256 标识，页面/帧使用独立 source ID。原图保留，派生图记录 EXIF 方向处理、旋转、透视四角、DPI 和图块坐标。坐标一律相对于当前处理图，原点左上，归一化 `[x0,y0,x1,y1]`，0–1。来源引用包含 revision，不能让旧坐标指向新的变换结果。

内容按逻辑单元编排，可以跨照片，也可以多个单元共享同一张照片。所有来源都应有覆盖记录；重复/排除/未识别区域需记录原因。脚本检查引用、结构及覆盖登记，是否遗漏笔迹由宿主对照全图确认。

符号表记录 LaTeX 记号、含义与作用域，不因同名字母跨章节而强行合并。每块标记原文、解释或修正；解释只进入复习版，修正保留 faithful 与 study 的分别内容。

## 拟定 CLI（P3/P4 实现）

入口为 `python3 <skill>/scripts/econ_note.py <command>`，所有项目命令接受 `--project PATH`。

| 命令 | 输入与行为 | 输出 |
| --- | --- | --- |
| `doctor` | 检查 Python 包、渲染器、编译器 | JSON 能力/缺失清单，不安装依赖 |
| `init` | `--inputs ... --title ... --mode faithful/study/both`；可选 `--domains ...` | 项目、来源与每页空单元，保留顺序 |
| `prepare` | 可选 `--source ID --rotate 90 --quad ... --dpi 300`；分块参数可调 | 全图、预览、分块、不可变 revision |
| `crop` | `--source ID --box x0 y0 x1 y1 --name NAME` | 有来源记录的 assets 图片 |
| `unit` | `--id ID --title TITLE --sources ...` | 新的空单元；已有单元拒绝覆盖 |
| `validate` | 读取 JSON、片段与素材 | `errors`、`gaps`、`warnings` 分别返回 |
| `status` | 根据当前文件计算指纹 | 各单元待办、复核和构建新鲜度 |
| `assemble` | `--mode faithful/study`，可选 `--allow-partial` | LaTeX 工程；保存旧构建并使旧结果失效 |
| `compile` | `--mode ...`，可选 `--isolate-failures` | 新编译 PDF 或错误报告；不以旧 PDF 判成功 |
| `render` | `--mode ...` | 本次 PDF 页图及渲染状态 |
| `review` | `--kind content --unit ID` 或 `--kind layout --mode ...`；`--note` 必填 | 宿主对当前内容/页面的复核声明 |
| `package` | `--mode ...`，可选 `--allow-unreviewed` | 独立 LaTeX 工程 ZIP、PDF 与交付说明 |

为避免 JSON 转义 LaTeX，正文使用 `.tex` 文件引用；可选课程公共 preamble 也使用文件引用。输出采用 JSON，路径供宿主直接读取。命令成功返回 0；参数、结构、缺依赖或操作失败返回 2；存在缺失/部分成功/未复核交付返回 3。`status` 返回 0 表示查询成功，不表示课程处理完成。

## 状态与失效规则

单元转录、内容复核、组装、编译、页面复核分别记录，不能用单一 `done` 标记。

- 单元摘要指纹包含单元 JSON、正文文件、引用来源 revision、素材内容和符号表；任一改变使内容复核失效。
- 构建指纹包含项目、所有单元、正文、素材与模板；重新组装清除旧 PDF/预览有效性。编译前比对当前输入与组装指纹。
- 编译检查退出码与本次 PDF，不接受上次残留文件。每次尝试独立目录和日志。
- 页面复核绑定当前 PDF 哈希和本次渲染页图；修改/重编译后重新确认。
- `review` 是宿主实际阅读后的声明，不是算法认证，不能自动调用代替检查。
- 不确定内容可编译，但带缺失/严重学术事项的结果是 `partial`。未复核的完整构建是 `unreviewed`；完成复核且无缺失才可标为 `reviewed`。

## 失败、恢复与交付

宿主最多进行 3 次针对同一失败的有依据修复；每次保留内容并比较改动。反复失败时可逐单元诊断并隔离编译失败单元，保留其源文件，在 PDF 对应位置显示简短缺失提示，交付状态为 partial。若故障来自公共模板或组装而所有单元均通过，不能把全文丢弃或虚报成功。

用户修正保留在正文及单元学术事项中；命令不改写正文。重新处理图像不会覆盖旧 revision，但使相关引用需要更新。长任务从 `status` 列出的过期/待处理单元继续。

交付包含 PDF、`.tex` 与模板、图表素材、块级来源记录及交付说明。ZIP 默认不包含整套私人原始材料、日志或预览；附录实际使用的局部截图随工程交付。路径全部相对化。未复核交付需要显式 `--allow-unreviewed`，其状态写入交付说明，正文不展示工具状态。

## 开发验证与后续验收

开发期检查结构、状态、文件操作和最小合成内容的编译/渲染。真实板书、模型识别质量、长课程材料和跨宿主端到端运行结果在后续验收中确认；本规格不设置未经样本支持的准确率目标。
