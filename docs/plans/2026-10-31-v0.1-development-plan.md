> 执行对象：后续负责本仓库开发的 Codex / coding agent。
> 状态：P1–P5 首版核心开发完成；真实材料验收、Claude Code 模型端到端验证及 DSH 专用加载仍待开展。
> 日期：2026-10-31（Asia/Shanghai）。
> 原维护者当前项目授权（外部 fork 不继承）：按 P1–P5 连续开发，审查通过自动合并；真实样本测试与验收后置。

## 1. 目标与已确定决策

开发 `advanced-econ-note2pdf` skill：将高级经济学板书照片、手写笔记 PDF 转换为可直接阅读、复习的 LaTeX 编译 PDF，同时交付可编辑源码和所需图表素材。

以下是用户已确认的要求，实施时不要重复询问：

| 项目 | 决策 |
| --- | --- |
| 输入 | 两种材料都支持，优先板书照片；关注反光、透视、跨图推导、重叠拍摄与擦写更正 |
| 学科 | 宏观、微观、计量、经济数理；公式、图、表、文字与推导均属于内容，不能只做公式 OCR |
| 使用入口 | 在 Codex、Claude Code 或 DSH 等 agent 工具中加载 skill，使用宿主模型 |
| 模式 | 每个转换任务在未指定时询问：忠实转录、复习讲义、两者都要；沿用用户已经给出的选择 |
| 阅读目标 | 逻辑连贯、内容完整、符号一致、排版清楚，适合直接复习 |
| 提示策略 | 少防御性表述；普通疑点与必要整理说明进附录，技术日志进工程文件；严重错误或关键内容无法识别时才在正文局部提示 |
| 验证安排 | 先开发；真实材料测试、验收样本和质量评估在首版开发完成后再安排 |
| 开发方式 | 先制定可执行计划，再按阶段开发；使用 Git 分支、提交、评审和可追踪的进度记录 |

首版不扩展为 Web 服务、独立 OCR 模型训练、付费识别服务集成或多人协作平台。不将子 agent、专有 SDK 或某个宿主的隐藏能力作为核心依赖。

## 2. 启动与工作规则

1. 读取根目录 `AGENTS.md` 和本计划，检查 `git status`、当前分支、远程和最近提交。
2. 确认本轮用户要求的是规划、实施还是修订。规划任务只改文档；收到实施指令后，在已有授权范围内连续推进，阶段结束不需要机械式请求批准。
3. 从远程最新适用基线建立任务分支。建议一个阶段一个 PR；必要时按可独立评审的变更拆分。上一阶段尚未合并时，明确依赖分支与 PR，不混入无关变更。
4. 严格按 P1 → P2 → P3 → P4 → P5 执行。先写清接口和不变量，再写实现；发现接口需要修改时，同步修改规格、调用方与执行记录。
5. 每阶段结束填写文末执行记录，保留实际验证证据。只有该阶段产物与完成条件均满足时才能勾选完成。
6. 不要求用户现在提供测试材料。缺少样本不阻塞规格、规则、脚本、模板与宿主适配开发；也不能据此声称真实识别效果已验证。

### Git 交付约定

- `main` 保存可追溯基线；初始化后，阶段变更通过任务分支与 PR 进入主线。
- 建议分支：`docs/v0.1-contracts`、`feat/economics-guidance`、`feat/material-pipeline`、`feat/latex-delivery`、`feat/host-packaging`。
- 建议提交使用 `docs:`、`feat:`、`fix:`、`chore:`，每次提交只表达一个清楚的变更目的。
- PR 描述必须区分“已实现”“已自检”“未做真实材料测试”“宿主尚未验证”；保持事实准确。
- 用户已授权本项目已授权任务的 PR 在审查无阻塞问题、适用检查通过并满足仓库规则后自动合并；合并前核对最新提交，不再逐次请求确认。
- 计划里列出的脚本名是拟定接口。可以因实现需要调整，但必须同步调用示例、目录说明与规格。
- 首次仓库初始化只建立 README 与忽略规则；本规划工作在独立文档分支提交，不产生可用版本声明。

## 4. 五个实施阶段

### P1 — 冻结首版规格与数据契约

**目的：** 使后续 agent 无需重新猜测产品目标、状态含义或脚本接口。

**任务：**

- [x] 编写 `docs/spec.md`，写清支持的输入、输出目录、三种模式、正文与附录政策以及暂不支持的能力。
- [x] 设计运行目录：不可覆盖的原始材料、处理图像、裁切素材、中间内容、LaTeX 工程、交付 PDF、预览、日志和状态分开放置。
- [x] 定义材料标识、原文件指纹、PDF 页码、图像尺寸、变换记录和坐标约定；裁切区域须能追溯到来源，不能只留下最终小图。
- [x] 定义内容契约：逻辑单元、内容块、公式/图/表、来源引用、模式版本、符号表、覆盖清单、疑点、修订记录和阶段状态。选取一种可由宿主编辑并由脚本校验的格式，记录选择理由。
- [x] 定义内容块的来源类型：原始材料、解释性补充、用户修正。补充内容与原文分别记录，避免复习版反向污染忠实版。
- [x] 定义最低状态粒度：待处理、已转录、已组装、编译失败/成功、已对照复核、有待确认事项。内容改变后相关编译和复核状态必须失效。
- [x] 明确 CLI 接口草案：环境检查、项目初始化、材料准备、裁切、结构校验、组装、编译、渲染、状态查询和交付打包。
- [x] 明确失败输出与退出语义：部分产物可保存，但不得把部分成功写成整份完成；编译成功不等于内容正确。

**完成条件：** 每个后续模块的输入、输出与责任可从规格定位；关键状态与异常没有相互矛盾的定义；三种模式和附录策略均有具体处理规则。

**提交产物：** `docs/spec.md`；实现确定后供宿主使用的简明契约放入 `references/content-model.md`，避免两份定义长期不一致。

### P2 — 编写经济学知识规则与宿主工作流

**依赖：** P1 的模式、来源和内容契约。

**任务：**

- [x] 编写精简的 `SKILL.md`：触发范围、必要交互、工作流、交付要求及参考文件的读取条件。三种模式未指定时才询问，不引入固定的长问卷。
- [x] 编写 `workflow.md`：先看全图理解布局，再看高清局部识别；登记每个可见内容块，再建立跨图顺序、重复区域、擦写更正和未完推导的关系。
- [x] 编写 `editorial.md`：忠实版保留内容与推导顺序；复习版可重新分节、补连接解释和明确的补充推导；双版本共享已核对的转录基础与来源数据。
- [x] 建立四个学科参考文件，重点写会改变识别和整理决策的规则，不复制教科书概论：

  | 学科 | 必须覆盖的处理规则 |
  | --- | --- |
  | 宏观 | 时点与期望算子、存量/流量、人均/总量、实际/名义、离散/连续时间；预算与资源约束、Euler 方程、横截条件、稳态和动态系统；相图中的零运动线、箭头与稳定路径 |
  | 微观 | 目标与约束、内点/角点、KKT 和互补松弛；Marshall/Hicks 需求、对偶、包络和 Slutsky 分解；均衡条件、博弈的行动/信息/收益对应及福利比较 |
  | 计量 | 总体/样本、参数/估计量/统计量、条件期望、识别/估计/推断；矩阵维度、概率极限与渐近分布；回归表中的标准误类型、样本量、固定效应、显著性与单位 |
  | 经济数理 | 定义域与量词、标量/向量/矩阵、转置与逆、梯度/Hessian；必要/充分条件、凸性/凹性、边界、概率条件、差分/微分方程和证明依赖 |

- [x] 制定疑点分级：不影响结论的阅读疑点进入附录；改变符号方向、条件或结论的歧义在正文对应位置简短提示；无法确定时保留原图或缺失位置，不输出貌似确定的替代结论。

**完成条件：** agent 能按学科选择参考文件并执行完整工作流；规则同时覆盖公式、推导、图、表和文字；忠实性、整理权限和阅读体验之间有明确边界。

**提交产物：** `SKILL.md` 与实际被引用的 `references/` 文件。尚未实现的命令标明依赖阶段，不宣称可运行。

### P3 — 实现材料预处理、来源管理与断点状态

**依赖：** P1 契约和 P2 识别工作流。

**任务：**

- [x] 建立 Python CLI 与必要依赖声明，提供环境检查。优先使用标准库；图像处理选 Pillow，PDF 页面渲染选可用本地工具。依赖缺失时给出具体诊断，不自动换成外部模型服务。
- [x] 支持明确顺序的多图和 PDF 页面导入；目录排序作为建议并保存。复制原始材料并计算指纹；同名文件不互相覆盖，相同内容不静默删除。
- [x] 实现 EXIF 方向处理、可控旋转、轻度对比度增强、可选透视校正和分块。HEIC 等格式通过可用解码器处理；不支持时明确报告并保留输入。
- [x] 同时保存全图上下文和可辨认笔迹的高清局部；分块有重叠并携带坐标。颜色包含经济含义时保留彩色，不默认灰度化。
- [x] 实现区域裁切及素材登记；所有派生图片记录处理参数与来源。更新图片后使依赖旧坐标的内容状态失效，避免错误来源定位。
- [x] 实现内容契约校验：引用存在、标识唯一、来源区域有效、模式合法、覆盖记录完整。结构校验不能声称检测了语义遗漏。
- [x] 实现按逻辑单元保存进度、恢复和指定单元重做；写入采用可恢复方式，避免半写文件；保留用户修正，不因再次初始化而覆盖已有工作。
- [x] 保留块级覆盖清单：已纳入、确认重复、明确排除、无法识别。排除和合并必须有原因；不能因为某页已有一个公式就将整页标记完成。
- [x] 在 `docs/development.md` 写明可复现命令、依赖范围、有效环境检查结果和已知格式限制。

**完成条件：** 脚本能够准备材料并产生可追溯的工作目录；恢复和变更失效逻辑已实现；模型识别仍由宿主驱动；没有将真实板书识别效果写成已通过。

**开发期验证：** 语法/导入检查、CLI 自检及必要的最小文件操作检查；不建立真实材料验收集。

### P4 — 实现讲义组装、经济学图表和 PDF 交付

**依赖：** P2 编辑规则和 P3 内容/素材接口。

**任务：**

- [x] 建立中文与英文数学兼容的 LaTeX 模板，优先 XeLaTeX + latexmk。字体与替代方案明确记录；不把本机独有字体写成必要依赖。
- [x] 提供经济学常用算子、定理/证明环境、分步推导、矩阵、分段函数、跨页表格、图题与交叉引用。自定义宏避免抢占常见变量名称。
- [x] 实现确定性组装：从内容块生成章节，稳定编号与来源映射；三种模式共享源数据，输出文件明确区分忠实版和复习版。
- [x] 支持 TikZ/PGFPlots 重绘含义清楚的示意图；真实统计图保留数据与单位。只有示意图时不制造精确数值，不能为了绘图方便擅自更改函数或参数。
- [x] 重绘无法可靠保留含义时嵌入清晰原图区域，保证字号、裁切、比例与图题适合阅读；图中颜色、箭头、虚实线和分面关系须保留。
- [x] 实现表格排版：列标题、单位、精度、缺失值、标准误/括号行、表注完整；宽表和长表使用合适布局，不以过度缩小字号解决溢出。
- [x] 实现附录生成：聚合有阅读价值的未决事项、原文修订和整理说明，并关联章节/公式。空附录不生成；工具故障、重试次数和堆栈不进入正文或学术附录。
- [x] 实现编译、日志定位与渲染入口。使用当前构建结果与退出码判断成功，防止把旧 PDF 当作本次成功；记录警告和错误供宿主修复。
- [x] 定义宿主修复循环与有限重试：修复当前单元，核对差异和内容量。不能通过删除图、公式、条件或证明步骤消除编译错误。
- [x] 实现失败隔离与部分输出：保留失败内容和来源；若交付部分讲义，缺失位置给出必要提示，结果状态明确为部分完成。
- [x] 实现最终复核流程：对照原图检查内容覆盖与符号，检查推导依赖和经济含义，再检查渲染页中的截断、分页、重叠、可读字号与图表位置。
- [x] 交付可编辑的独立 LaTeX 工程、PDF、必要素材和机器可读来源记录。交付工程使用相对路径，不依赖开发者本机绝对路径。

**完成条件：** 从合法中间内容到 LaTeX/PDF 的处理链已实现；一般处理问题不会流入正文；失败、部分成功、编译成功、已复核之间有清楚区分。

**开发期验证：** 用最小合成内容检查模板编译、基本图表排版和渲染接口；这只验证工程连通性，不代替真实材料测试、模型效果测试或用户验收。

## 5. 必须保持的不变量

1. **原始材料可追溯。** 原文件保留，派生图像记录变换，内容块可关联到具体页/图和区域。
2. **不以常识替代证据。** 不能把辨认不出的内容自动换成标准公式、典型图或估计数字。
3. **逻辑完整性先于表面完整。** 目标、条件、符号、推导与结论需衔接；缺失关键条件不能只在附录轻描淡写。
4. **复习版有清楚的编辑边界。** 可以改善顺序、语言和衔接；补充推导须有可辨认身份，新增实质假设在使用位置交代。
5. **正文保持可读。** 不显示识别置信度、工具报错、流水线状态或反复的免责措辞；严重内容缺失局部提示即可。
6. **图表属于知识内容。** 轴、方向、交点、标签、单位、表注与数字都是复核对象，不是装饰。
7. **编译与内容审阅分离。** 不能因 PDF 存在、返回码为零或 schema 校验通过，就宣称转录完整正确。
8. **处理可恢复。** 单元失败不丢失此前成果；重做不会静默覆盖用户修正；过期状态不能作为交付依据。
